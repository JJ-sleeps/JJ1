## Reading these numbers

- **Memory**: JJ1's static tier used 10-27 MB per page against roughly 540-1650 MB
  (summed working sets) or 210-785 MB (private bytes) for headless Chrome. That is
  a 95%+ saving on pages that need no JavaScript, which beats the 70-85% target.
  It says nothing yet about JavaScript pages, where a JS tier will cost far more.
- **Tokens**: a default `jj1_open` is a median 6.5x smaller than the browser's DOM,
  and 50-100x smaller on large pages (Wikipedia, GitHub, react.dev). The plan's
  "10-50x" hypothesis holds for big pages, not for small ones: there is a floor of
  about 100 tokens of header and markers, and the default open is capped (1500
  tokens of text, 80 actions), so the rest of a long page costs further calls.
- **Coverage**: 3 of 30 pages need JavaScript and came back as empty shells
  (correctly reported as such). 3 were refused because their robots.txt disallows
  JJ1; Chrome ignores robots.txt, so that is a policy difference, not a failure.
  1 (gnu.org) timed out for both tools.
- **Time outlier**: sqlite.org/lang_select.html took 96.6 s in this run. A rerun
  took 4.0 s (3.97 s of it network), so it looks like a slow response from the
  server rather than JJ1 processing, but the cause was not established.
- One run per page; no repeats, so individual timings are noisy.
